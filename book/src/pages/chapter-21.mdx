# Chapter 21: User Profiles & Clinical Tuning

No single scanning configuration works for all users, or even for the same user throughout a single day. 

A **User Profile** captures an individual's motor, visual, and cognitive capabilities, translating them into specific software timing parameters, layouts, and input filters.

## Core Parameters Captured in a Profile

1. **Motor & Input Capabilities:**
   - Mean switch reaction time (`RT`) and standard deviation (`SD`).
   - Required acceptance delay (ms) and debounce threshold.
   - Switch count (1-switch auto-scan vs 2-switch step-scan).
2. **Visual Preferences:**
   - Highlight contrast, border thickness, font size, and color themes.
   - Preference for Block vs Point highlighting technique.
3. **Cognitive & Language Settings:**
   - Grid size (`N`), scan pattern (Linear, Row-Column, Elimination).
   - Word prediction list candidate count (3–6 items) and layout frequency.
4. **Fatigue Profiles (Diurnal Adjustments):**
   - For progressive conditions (e.g., ALS/MND or Muscular Dystrophy), muscle strength and reaction time change between morning and afternoon.
   - Profiles should store **Morning (Fresh)** and **Afternoon (Fatigued)** presets with automatic or 1-tap timing adjustments.

## Example Clinical Presets

- **Spasticity / Tremor Profile:** Long acceptance delay (400–600 ms), debounce enabled (100 ms), slower scan rate (+25% buffer), block highlight technique.
- **Low Vision / CVI Profile:** Thick border highlights (8px), auditory speech prompting enabled, high-contrast yellow/black theme, 1st-item extended pause.
- **High Efficiency / Advanced Profile:** Fast scan delay (500–800 ms), thin point highlighting, frequency-based ETAOIN SHRDLU grid, 3-candidate word prediction.

<div class="warning-box">
  <strong>Clinical Golden Rule:</strong> Always provide a "Safe Default Profile" (slow scan rate, wide acceptance delay) that the user can immediately revert to if settings become misconfigured.
</div>
